\title{SparseTreePIR: Active-Interval Coloring for Batch Private Information Retrieval of Sparse Merkle Proofs}

\author{\IEEEauthorblockN{Anonymous Author(s)}}

\begin{document}

\maketitle

\begin{abstract}
Sparse Merkle Trees (SMTs) support compact membership proofs over large logical address spaces by combining non-default sibling digests with public default-empty hashes. A standard proof request, however, reveals the queried coordinate and its authenticated path. We study target-private retrieval of SMT membership proofs for a fixed public snapshot. The central challenge is that the verifier-facing proof and the PIR-facing database are different objects: the verifier expects a standard height-$h$ SMT proof, whereas the PIR backend should query only proof material that cannot be reconstructed from public defaults.

We characterize this PIR-facing object as the active proof-bearing interval forest: the minimal set of non-default sibling digests that can appear in occupied-leaf membership proofs, together with served target-leaf intervals identifying when each digest is needed. SparseTreePIR places only these active proof records in PIR subdatabases, colors the interval forest so that each retrieval contains at most one real record per color, and sends a fixed-shape real/dummy batch query. The client reconstructs the ordinary height-$h$ SMT proof locally by combining retrieved real digests with the public default-hash chain. Thus the verifier-facing proof length remains $h$, while the PIR-facing query width is the active width of the occupied-leaf skeleton rather than the logical tree height.

We further introduce \ActiveBalance{}, a subtree-level load refinement that preserves the one-query-per-color transcript while reducing the largest searched color store. On six SMT workloads, the active width is only $9$--$17$ for height-$128$ and height-$256$ proofs. Compared with Pruned TreePIR-$h$, SparseTreePIR uses $9.5\times$ fewer subqueries and a $2.5\times$ smaller largest searched store on height-$128$ workloads. Executable SimplePIR and PIANO runs show $2.1\times$--$2.3\times$ lower online communication than an optimistic PBC-style SMT baseline, without changing the underlying PIR primitive.
\end{abstract}
