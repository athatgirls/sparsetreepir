# 面向固定稀疏 Merkle 树的加权祖先染色

## 1. 问题重述

TreePIR 的核心目标是：

- 将树节点划分到若干颜色类（即若干子数据库）；
- 同一条 Merkle proof 上的节点颜色两两不同；
- 各颜色类尽量均衡，从而降低 PIR 检索的最坏开销；
- 不复制节点，因此总存储仍然是最优的。

对固定的 Sparse Merkle Tree，可以先像论文附录 J 那样做两步预处理：

1. 删除完全空子树，只保留真实非空叶及其祖先；
2. 将只有一个孩子的路径压缩，得到一个压缩后的 full binary tree。

压缩后，每条 root-to-leaf 路径对应一条“真实需要私有取回的证明路径”；被压掉的默认节点可以本地恢复，不必参与 PIR。

## 2. 新算法的核心想法

perfect tree 场景里，论文平衡的是“每种颜色包含多少个节点”。

但对固定稀疏树，这个目标不够精确。因为不同节点出现在证明里的频率不同：

- 一个节点如果覆盖很多非空叶，它会出现在很多 Merkle proof 中；
- 一个靠近稀疏分支末端的节点，只会出现在很少的 proof 中。

因此更合理的负载定义应是：

`weight(v) = 以 v 为根的非空叶数量`

如果客户端均匀地查询所有非空叶，那么节点 `v` 被访问的频率正比于 `weight(v)`。

所以，我们不再只平衡颜色类的节点数，而是优先平衡：

`W_c = sum(weight(v)) , 对所有 color(v)=c 的节点 v`

这比普通计数更贴合固定稀疏树上的真实检索负载。

## 3. 算法定义

记压缩后的树为 `T'`，根节点公开且不染色。

- 颜色数 `m` 取为 `T'` 中最长 root-to-leaf 路径长度。
- 对任意非根节点 `v`，必须满足：
  `color(v)` 不出现在从根到 `v` 的祖先路径上。
- 对较短 proof，客户端补 dummy PIR 查询到 `m` 次，以避免泄露路径长度。

算法分两阶段：

### 阶段一：加权贪心初始化

按拓扑从上到下扫描压缩树。

对当前节点 `v`：

1. 求出祖先路径上已经使用过的颜色集合 `A(v)`；
2. 候选颜色为 `[1..m] \\ A(v)`；
3. 从候选颜色中选取当前“加权负载最小”的颜色：
   `argmin_c (W_c, N_c, c)`

其中：

- `W_c` 是颜色 `c` 的总权重；
- `N_c` 是颜色 `c` 的节点数；
- 最后一项 `c` 只是打破平局。

这样天然满足祖先约束，并优先把高权重节点放到当前较轻的颜色上。

### 阶段二：局部重平衡

初始化后，反复执行下面的合法重染色操作：

- 选一个当前较重颜色 `a` 上的节点 `v`；
- 尝试把它改染成较轻颜色 `b`；
- 仅当 `b` 没有出现在 `v` 的祖先和后代中时，这次重染色才合法；
- 如果这次移动能降低目标函数
  `(max W_c - min W_c, max N_c - min N_c)`
  就接受。

直到没有进一步改进为止。

## 4. 与 TreePIR 的关系

这个算法和 TreePIR 的关系可以概括成：

- TreePIR 解决的是 perfect tree 上的“结构无关”统一染色；
- 这里解决的是 fixed sparse tree 上的“拓扑自适应”离线染色。

两者共同点：

- 都保持 ancestor-distinct 约束；
- 都不复制节点，因此没有额外存储冗余；
- 都能把证明检索转化为“每种颜色一次 PIR”。

两者不同点：

- TreePIR 平衡的是颜色类大小；
- 这里优先平衡的是颜色类承载的访问权重；
- TreePIR 的颜色方案只依赖树高；
- 这里的颜色方案依赖固定稀疏树的实际拓扑。

## 5. 原型实验结果

对论文附录 J 的示例叶集合 `{16,17,19,22,28}`，压缩后树的最长证明长度为 4，因此使用 4 种颜色。

原型结果：

- 新算法的加权负载为 `[4, 4, 3, 3]`，加权 gap 为 `1`
- 朴素层染色的加权负载为 `[5, 4, 3, 2]`，加权 gap 为 `3`
- 祖先约束验证通过

这说明在 fixed sparse tree 上，按“访问权重”而不是“节点数”去做均衡是有意义的。

## 6. 可写成论文的表述

如果你后面要把它写成论文/开题，可以把这个方法命名为：

- `Weighted Balanced Ancestral Coloring for Fixed SMT`
- 或 `Topology-Aware TreePIR Coloring`

一个自然的定理方向是：

- 正确性：算法输出满足祖先冲突约束；
- 存储性：每个节点只出现一次，因此总存储最优；
- 隐私兼容性：固定用 `m` 次查询，短路径补 dummy，不泄露目标叶位置；
- 负载性：该算法最小化或近似最小化颜色类的加权失衡。
